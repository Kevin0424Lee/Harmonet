# 전체 규칙 검정력 (Week2-F4-3) — seeds=20, 부트스트랩 2000, 귀무 300

추정량: (i) 교차 적합 (ii) 직접+노이즈 보정 (iii) 가산 귀무 모수적 부트스트랩. 규칙 R1 = CI 하한>0 ∧ 점추정≥10pp, R2 = CI 하한>5pp.
통과율·포함률은 20회 정확 이항(Clopper-Pearson) 95% 구간과 함께. **참 gap 이 목표값이 되도록 상호작용 배율을 seed 마다 맞춘 합성 자료**이며,
(i) 의 CI 가 맞는 대상은 '2표본 선택기의 기대 성능'이고 oracle gap 검출 검증이 아니다 (D6 §2). (ii)(iii) 의 CI 는 oracle gap 을 겨냥한다.

## §4 첫머리 — 자명 통과 확인 (Week2-G1): 현행 규칙 (i)+R1 은 구조 없는 데이터에서 통과한다

F4 생성기에서 **σ_γ = 0**(과제×arm 상호작용 없음), k=3, seed 20. 결정적 반복(ρ≥0.9)이면 (과제, arm) 의 독립 실현만으로 교차 적합 gap 이 15~17pp 가 되어 R1 을 넘는다 —
이것이 '독립 바닥'이며 일반화 정책이 먹을 수 있는 구조가 아니다 (`scripts/gap_floor.py --g1`, `gap_floor_g1.json`).

**'교환 귀무 0/20' 이 무엇이었나.** F4 의 크기 검사에 쓴 '교환 가능 귀무' 는 과제마다 잠재 결과 하나를 **모든 arm 이 공유**하게 만든 것이다 — 과제 안에서
arm 간 결과가 동일하므로 바닥이 정확히 0 인 귀무다. 이는 arm 라벨을 순열해도 데이터가 안 바뀌는 귀무이지, 우리 데이터(arm 마다 독립 실현)의 귀무가 아니다.
우리 데이터의 귀무는 '가산 + 독립 실현' 이고 그 바닥은 위 표대로 13~27pp 다. F4 의 (iii) 가 X > 27pp 로 나온 것은 바닥 17pp + 초과 10pp 를 요구한 결과이므로
'제외' 판단이 틀렸고 (iii) 의 방향이 맞았다 (G4 정정).
