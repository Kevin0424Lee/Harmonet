## 2. 풀 관문 (탐색 자료에서 판정)
- 탐색 100 의 6 arm 성공률 중 **최고 점추정 ≤ 80%** → 확인 단계 진행. **초과 → 보류** (과제 선별·문턱 상향으로 살리지 않는다; 다른 풀은 새 사전 등록).
- 80% 와 "여지 ≥ 2×MDE" 는 **운영 기준**이다: 여지 = 1 − 최고 arm 성공률, MDE = 10pp 실용 문턱. 원 등록값 70 은 유도 없이 A 창을 복사한 값(notes 검토 오류 표),
  80 은 프로브(B 75%) 후 개정한 값 — 개정 이력과 판정 자료(프로브 60 ≠ 탐색 100 ≠ 확인 200)를 분리해 둔다.

## 3. 탐색 단계 절차 (전부 동결 대상)
1. **0회차**: 탐색 첫 10 과제에서 B-expert 1회 호출(max_tokens 4096, 상한 없음) → b_cont = 비용 중앙값. 이후 모든 계속 arm 의 max_tokens 규칙에 적용, 거부율 기록.
2. 6 arm k=1 실행 (T / A-self / A-self×k / A-role / B-expert / B-solo; A = claude-haiku-4-5, B = claude-sonnet-4-6, temp 0.2). 뒤집힘 부분집합 30 은 A-self·B-expert 만 k=2.
3. 특징: 사전 등록 메뉴 = `benchmark/features.FEATURE_SPECS["post"]` (pre 17 + post 11 = **28 열**, `FEATURES_VERSION`). 여기서 **최대 20 열** 선택 (CV 로).
   λ ∈ {0.3, 1.0, 3.0} (기본 1.0) 선택. 학습: P2-post(주), P2-pre, P1. CV = K5 × R20, 과제 부트스트랩 1000 (GroupKFold, J1) — **모델 선택용**이지 판정이 아니다.
   특징 순열 p 는 진단으로만 기록한다 (귀무 "특징 ⟂ 결과" ≠ "정책 이득 ≤ 0").
4. 고정 전략 **â = 탐색 100 에서 성공률 최고 arm** (동점 ARMS 순서 앞).
5. **동결 커밋**: 특징 부분집합·λ·P2-post/P2-pre 계수·P1 표·â·b_cont·seed 를 파일로 저장하고 커밋 → 해시를 이 문서 표에 기입. 이후 변경 = 새 사전 등록.

## 4. 확인 단계 판정 (사전 등록)
- 과제별 **d_i = y[i, π̂_post(i)] − y[i, â]** (y ∈ {0,1} 히든 통과, k=1).
- **주 검정**: 정확 McNemar, **단측** — b = #{π̂ 성공 ∧ â 실패}, c = #{π̂ 실패 ∧ â 성공}, p = P(Bin(b+c, ½) ≥ b).
  **통과** ⇔ p < 0.05 ∧ 평균 d ≥ 10pp. 그 외 **미확인**. ("없음" 결론은 쓰지 않는다.)
- CI: d_i 의 과제 부트스트랩 1000 (학습 없음, 재표집만). 보고용.
- 의미: 통과 = **"양의 정책 이득의 증거(p<0.05) + 점추정이 실용 문턱 10pp 이상"**. "≥10pp 를 입증" 한 것이 아니다 (CI 하한이 10pp 를 넘는다는 뜻이 아님).
- 미확인 시 결론 문장: "BCB 적격 풀의 확인 200 에서, 탐색 100 으로 동결한 정책 π̂_post 가 고정 전략 â 를 이긴다는 증거(단측 McNemar p<0.05 ∧ 평균 이득 ≥10pp)를
  얻지 못했다 (미확인; 참 이득이 작은 경우와 특징이 유형을 담지 못한 경우를 구별하지 못한다)."
- **부차** (전부 기술·대응 검정, 판정에 안 씀): P2-post vs P2-pre 과제별 차이(대응 McNemar) = 실행 후 상태 특징의 추가 가치(절제); P1 대응 차이; oracle(1회 실행
  최대의 표본 내 통계 — 상한 아님, J6 구분); arm 별 성공률·$·거부율; 정책 선택 분포와 $; **총비용** = arm + 상태 취득(s0 생성 + 가시 검증) + 0회차 + 뒤집힘 (원장).
- **금지**: 확인 결과 열람 후 문턱·과제·분석 변경. 확인 집합에서 어떤 학습도 하지 않는다.
- **결론 범위** = 이 BCB 적격 풀(403). 다른 풀·모델로 일반화하지 않는다. 방법을 바꾸면 이 200 은 재사용 불가 → 예비 103.

## 5. 실행·비용·중단
- 실행 게이트(J5): `--backend anthropic` 명시 ∧ 이 설정 파일 해시 일치 ∧ s0 가져오기 완료 ∧ 0회차 b_cont 완료 ∧ 뒤집힘 설정 존재 ∧ Docker 사전 점검 — 하나라도 없으면 호출 0.
- 비용(과제당 6 arm ≈ $0.04 프로브 실측): 탐색 = 41 s0 신규 ≈ $0.15 + 41×6 + 59×5(T 무료) ≈ $4 + 뒤집힘 30×2 ≈ $0.5 + 0회차 ≈ $0.2 → **≈ $5**;
  확인 = 200×6 ≈ $8 → **≈ $9** (여유 포함). 원장 **cap $16** (`HARMONET_BUDGET_CAP=16`).
- 중단: 예약 거부·커밋 후 초과·미측정·인프라 장애 → 부분 결과 저장(완료 arm 포함, J2), 종료 코드 2, 재개는 같은 config_hash 의 멱등 재실행.
- **재시도·시도별 귀속 (K2, `benchmark/runloop.py` 와 같은 문장)**: SDK 재시도 0, 재시도는 원장 경로에서만(최대 3회, 시도마다 예약·확정, HTTP 요청 수 == 원장 건수).
  (a) 성공 시도: 실측 비용. (b) 요금 없음이 확실한 실패(HTTP 429·400·401·5xx 응답, 서버가 처리 전 거부): actual=0, attempt_failed_unbilled=True, 예약 해제, 호출 수에 포함
  (429/5xx 재시도, 400/401 은 중단). (c) 처리 여부 불명 실패(타임아웃·연결 끊김): 예약액을 보수적으로 확정, unknown_cost=True, n_unpriced(n_unknown_attempts)에 포함.
  **같은 과제에서 (c) 가 1회면 재시도 계속, 2회면 그 arm 중단**(기존 산출물로 종료, 확정 예약액은 그 arm 비용). arm 비용·호출 수·잔여 예산에 모든 시도 반영.
- 통과 시 다음(4~6주차): 같은 확인 200 자료에서 REDEREF 식 사후분포 라우터·KABB 식 부분집합 선택과 직접 비교 (재실행 없이 가능한 범위), 반사실 실측은 새 자료.
