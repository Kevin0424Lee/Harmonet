## 3. 무엇이 안 맞는가

1. **[30, 70] 창과 현 모델 세대.** haiku-4-5 는 함수 단위 벤치마크(HumanEval 96%, MBPP+ 85%)를 이미 천장에서 푼다. 창 안에 든 것은
   라이브러리 호출·긴 사양의 BCB 뿐(63%). 그런데 같은 BCB 에서 B(sonnet-4-6)는 75% 로 창을 넘는다 — "B 가 A 를 도울 여지" 를 남기려던 B ≤ 70% 조건과
   "A 가 혼자 못 푸는 과제가 충분히 있다"는 A 창을 **한 풀에서 동시에** 만족시키는 조합이 이 모델 쌍으로는 좁다.
2. **B ≤ 70% 조건의 의미가 약하다.** 설계(§0)의 질문은 "s0 에서 종료/자기수정/전문가 추가가 갈리는 경우가 있는가" 이다. B 가 잘 푸는 것 자체는
   B-solo arm 의 경쟁력을 뜻할 뿐, gap 의 존재를 부정하지 않는다(과제별 교차: 둘 다 pass 36, A 만 2, B 만 9, 둘 다 fail 13 — "B 만 9" 가 곧 갈림의 후보다).
   B 상한은 "B-solo 가 최선 고정 전략이 되어 나머지 arm 이 무의미해지는" 상황을 피하려는 운영 기준이었고, 점추정 75% 는 그 우려를 확인하지도
   부정하지도 못한다(CI 하단 62.8%).
3. **가시 신호가 약하다.** BCB 가시 doctest 통과 ↔ 히든 통과 불일치가 A 16/60, B 11/60. 자기 수정·전문가 arm 이 "가시 검증 출력을 보고" 행동하는
   설계에서 가시 신호가 이 정도로 성기면 arm 간 차이가 노이즈에 묻힐 수 있다 (검정력 계산 §4.5 이전에 알아야 할 사실).
4. **표본·비용은 이제 문제가 아니다.** BCB 적격 409(확인 349), 프로브 2 arm 합 $0.57. 6 arm × k=3 × 349 과제는 비용 추정이 필요하지만
   프로브 단가(A $0.003, B $0.006/과제)로는 수십 달러 규모.
5. **오염.** BCB 는 2024-06 공개, 두 모델의 컷오프 이후가 아니다. 히든 test 는 공개 저장소에 있다(가시 doctest 와 함께). MBPP+·HumanEval 과 같은 한계.

## 4. 사용자·교수님 판단이 필요한 대목 (제안이 아니라 선택지)

a. **규칙 유지**: BCB unconfirmed. 이 모델 쌍으로 [30,70]∧B≤70 을 만족하는 풀은 찾지 못했다고 보고하고 멈춤 (현재 상태).
b. **B 조건 재정의**: B 상한을 없애거나 "B − A ≥ x pp"(갈림의 여지) 로 바꾼다. BCB A 63% / B 75% 는 그 기준에서는 후보가 된다.
   단 사전 등록 뒤의 규칙 변경이므로, 바꾼다면 **새 프로브 ID 60개**로 다시 프로브해야 한다(지금 60개는 탐색용으로 격하).
c. **모델 쌍 재선정**: A 를 더 약한 모델(예: haiku 이전 세대·오픈 모델)로 낮춰 창 안에 넣는 방법. 연구 질문이 "현 세대에서 갈림이 있는가" 라면 답을 비켜간다.
d. **연구 질문 축소**: "갈림의 존재" 대신 "가시 신호가 히든 결과를 예측하는가" 를 먼저 묻는 것(§3-3). 프로브 4 데이터만으로도 표는 나온다.
